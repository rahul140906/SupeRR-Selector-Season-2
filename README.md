# SupeRR Selector — Season 2

A reproducible Python pipeline for identifying IPL and Men's T20I batters and bowlers whose historical performance metrics are strong in defined pressure situations.

## What this repository contains

- `pressure_model_unforced.py` — pressure feature engineering, player-level feature construction, logistic-regression calibration and ranking pipeline.
- `data/` — the CSV inputs required by the script.
- `results/` — CSV outputs generated by running the included model on the included data.
- `requirements.txt` — Python dependencies.

## Scope of the included run

The script filters matches dated **1 January 2022 through 30 November 2026** and includes IPL seasons and Men's T20Is. The data supplied with this project currently spans **22 January 2022 through 1 November 2026**.

The run included with this repository processed:

- 853 matches (371 IPL and 482 Men's T20Is)
- 194,014 ball-by-ball records
- 157 eligible batters
- 231 eligible bowlers

Eligibility thresholds in the code are 300 batting balls and 60 pressure-weighted batting balls for batters; 30 bowling overs and 60 pressure-weighted legal balls for bowlers.

## Method overview

1. Match metadata is joined to ball-by-ball data and filtered to IPL and Men's T20Is within the configured date window.
2. The state before each delivery is reconstructed, including runs, wickets, legal balls, innings progress, current run rate and (for chases) required run rate.
3. Live pressure flags are assigned for urgent chases, late chases, chase wicket stress, first-innings rebuilds and first-innings death phases. The highest applicable live weight is used, with a knockout multiplier applied to qualifying deliveries.
4. Separate batting and bowling feature sets are calculated by format. Percentile features are shrunk towards the format midpoint based on pressure sample size.
5. Eligible IPL and T20I format scores are blended using 60% IPL and 40% T20I weights when both formats are available. Missing-format scores are not treated as zero; format coverage is retained as a feature.
6. Separate logistic-regression classifiers are fitted for batters and bowlers using the manual reference labels. Candidates are then sorted by their model score.

## Important interpretation and limitations

- `model_score` is a **relative classifier score**, not a calibrated probability that a player will succeed in a future match.
- The manual reference players are used as positive calibration examples. The model is therefore not an independent blind validation of those same selections.
- Players without a positive manual reference label are treated as the other class during fitting. They should not automatically be interpreted as poor players; this is a limitation of the available labels.
- The script does not create a held-out test set or report independent predictive-performance metrics.
- The generated model rankings are machine-generated candidate rankings. They are not the same thing as a final human cricket judgement or a squad-selection decision.
- Scorecard-level and delivery-level pressure classifications should be independently checked before making claims about specific innings or spells.
- The date window ends on 30 November 2026, but the included dataset ends on 1 November 2026. No matches after the dataset's latest date are represented in this run.

## Requirements

- Python 3.9 or later
- pandas
- numpy
- scikit-learn

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

## Run the model

From the repository root:

```bash
python pressure_model_unforced.py --data-dir . --output-dir .
```

On Windows PowerShell, the same command works when Python is on your PATH.

## Input files

| File | Purpose |
|---|---|
| `data/ball_by_ball.csv.gz` | Delivery-level batting, bowling, runs, extras and dismissal data |
| `data/matches.csv` | Match dates, competition IDs, innings settings, results and knockout indicator |
| `data/competitions.csv` | Competition names and match formats used to identify IPL and T20I matches |
| `data/manual_reference_labels.csv` | Positive reference examples for batter and bowler calibration |

`competition_team_player_mapping.csv` is not required by this version of the script and is therefore not included.

## Output files

The script writes the following CSVs to `results/`:

- `top20_batter_candidates.csv` and `top20_bowler_candidates.csv` — top 20 candidates by model score.
- `all_batter_rankings.csv` and `all_bowler_rankings.csv` — complete eligible-player rankings.
- `batter_learned_coefficients.csv` and `bowler_learned_coefficients.csv` — fitted logistic-regression coefficients, sorted by absolute magnitude.
- `batter_format_metrics.csv` and `bowler_format_metrics.csv` — player metrics by format.
- `run_summary.csv` — match, record and eligibility counts.

The included `results/` files are the output of a run of the included script against the included CSV inputs. Re-running the script will regenerate them.

## Reproducibility note

The script uses a fixed `random_state=42` for logistic regression. Results can still vary across library versions or changes to input data. For a strict reproduction, retain the exact input CSV files and dependency versions used for the run.
